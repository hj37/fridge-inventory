# 🌱 냉장고 숲

개인용 식재료 재고관리 웹사이트. Vite + Supabase + GitHub Pages.

## 기능
- 귀여운 이모지 아이콘으로 식재료 등록·수정·삭제
- 냉장/냉동/실온 분류, 검색, 소비기한순 정렬
- 먹은 수량 차감, 재고 종류 수에 따른 배지
- 이메일/비밀번호 회원가입·로그인과 사용자별 클라우드 저장
- 재고 텍스트 공유(Web Share / 클립보드)
- 쿠팡·컬리·네이버 쇼핑 검색 링크, 배민 공식 홈페이지 연결

쇼핑몰 계정·구매내역·장바구니 API 연동은 포함하지 않습니다. B마트는 배민 페이지에서 앱을 연 뒤 선택해야 합니다. 공유는 목록 텍스트이며 공동 편집이나 공유 링크는 아닙니다.

## 실행
Node.js 22.12 이상에서:

```sh
npm ci
npm run dev
npm test
npm run build
```

로그인 전에는 샘플 재고를 브라우저에 임시 저장합니다. 로그인하면 별도의 빈 개인 냉장고가 열립니다. 체험 데이터는 자동 업로드되지 않습니다.

## Supabase
프로젝트 `fridge-inventory` / 서울 리전.
프런트엔드에는 공개용 publishable key만 포함합니다. 재고 테이블의 RLS 정책이 로그인한 소유자만 조회·추가·수정·삭제하도록 제한합니다.

배포 후 Authentication → URL Configuration에서 Site URL 및 Redirect URLs에 실제 GitHub Pages 주소를 등록하세요. 확인 이메일에서 인증 후 앱으로 돌아와 로그인합니다. 비밀번호 재설정은 현재 앱에 포함되지 않습니다.

## GitHub Pages
`hj37/fridge-inventory` 공개 저장소에 이 폴더의 소스를 올리고 Settings → Pages → Source를 GitHub Actions로 설정하세요. develop push 시 `.github/workflows/pages.yml`이 테스트·빌드·배포합니다.

무료 플랜의 한도와 일시중지 정책은 공급자 정책을 따릅니다. 유료 플랜이나 별도 유료 서비스를 활성화하지 마세요.

## 저녁 레시피 찾기

재고 중 소비기한이 가까운 재료를 최대 6개 제안합니다. 수량이 없거나 날짜가 지난 재고는 제안에서 제외하고, 같은 이름은 한 번만 표시합니다. 재료를 선택하면 `재료명 간단 집밥 저녁 레시피` 검색어를 만들며 직접 수정할 수도 있습니다. 버튼을 누르면 유튜브 검색 페이지가 새 창으로 열립니다. API 키와 별도 서버가 필요하지 않으며, 영상 검색 결과를 사이트 내부에서 수집하거나 순위를 매기지 않습니다.

## 영수증 사진과 무게 재고

- `영수증 찍기`에서 촬영하거나 JPG/PNG 등 브라우저가 읽을 수 있는 사진을 선택합니다.
- 한국어·영어 Tesseract.js OCR은 브라우저에서 실행합니다. 사진과 OCR 원문은 서버에 업로드하거나 영구 저장하지 않습니다. 처음 실행 시 인식 엔진과 언어 데이터를 CDN에서 내려받으므로 네트워크와 로딩 시간이 필요합니다.
- 인식한 품목·구매 개수·단위·분류·보관장소를 수정하고 선택한 항목만 저장합니다. 가격·포장 용량·구매 개수는 다르므로 반드시 확인합니다. 인식이 어려우면 텍스트 붙여넣기와 직접 추가를 사용합니다.
- 기본은 새 재고 등록입니다. 기존 재고에 더하려면 반영 방법에서 대상을 고릅니다. 단위·장소·소비기한이 같아야 더할 수 있습니다. 소비기한은 사진에서 추정하지 않습니다.
- g/ kg/ ml/ L 단위는 `사용량 입력`으로 차감합니다. 단위 간 자동 환산은 하지 않습니다.
- 소스·장류(간장, 된장, 고추장, 소스, 드레싱, 기름, 조미료)를 이름으로 분류하며 사용자가 바꿀 수 있습니다.
- 로그인 계정의 한 영수증 반영은 DB 함수에서 원자적으로 처리합니다. 하나라도 실패하면 전부 롤백합니다. 동일한 사진 파일의 SHA-256으로 중복 반영을 막습니다. 같은 영수증을 새로 찍은 다른 사진까지 판별하는 기능은 아닙니다.
- 새 DB를 구성할 때 기존 `schema.sql` 다음 `receipt-schema.sql`을 적용합니다.
